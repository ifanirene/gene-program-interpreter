01

What the review found

The takeaway is not “make the prompt shorter” — that change is already in place. The next gains in quality come from better inputs, stricter evidence checks, and a rule for when to stop searching.

Bottom line

Keep the architecture. Change what counts as support.

Several design choices are sound: one isolated session per program, in-process read-only literature tools, raw payload capture, deterministic identifier resolution, and a graceful fallback. But right now a mechanism is marked supported as soon as any linked PMID or DOI resolves. Nothing checks that the abstract actually backs the mechanism, that the PMID and DOI point to the same paper, or that several program genes drive the mechanism rather than the perturbation regulators.

KeepIsolation, PubMed fetch-before-cite, raw payloads, tri-state network verification.
Fix firstEntailment, gene-defined themes, schema constraints, dead input knobs.
Do not cut blindlyThe observed sessions needed 34–49 reported turns, so a 12–15 turn cap is not justified by evidence yet.

04

High-yield adjustments

Ordered by expected scientific gain, not by how easy the code change is. The first three improve interpretation quality directly; the later ones make the system cheaper and more reliable.

01

Make “supported” mean supported

Right now it means only “one identifier exists and has not been retracted.”

impact: very high · effort: medium
Separate three things: whether the citation resolves, whether the paper actually backs the claim, and whether the cell or tissue context fits. Store the canonical abstract along with a short excerpt that supports the specific claim, confirm that excerpt really appears, then run a small adjudicator that returns entail / neutral / contradict. Until that exists, rename the visible badge to citation resolved.
02

Define themes from program genes first

Right now regulators seed themes “the same way” as program genes do.

impact: very high · effort: small
Work in two passes: first cluster program_genes + distinctive_genes; only then ask whether the regulators reinforce those themes, work against them, or fail to connect at all. Require at least two program genes for a module, unless the agent explicitly flags a single-gene exception. Regulators should never count toward that two-gene rule.
03

Feed the agent signal already computed upstream

The bundle throws away ranks, tissue, NCBI summaries, and strong enrichment hints.

impact: high · effort: small–medium
Fix the bundle: add loading rank, genuinely unique genes from outside the top-loading set, tissue, canonical gene summaries and aliases, and the top three non-overlapping enrichment terms with their FDR and gene overlap. Treat enrichment as a starting hypothesis, never as literature evidence. This alone would have pointed to P10’s cilium program before dozens of single-gene searches.
04

Use an evidence budget, not a blunt turn range

The latest agents made 20–34 searches each and still logged only 53% of them in queries[].

impact: high · effort: medium
Retrieve in stages: discover themes → gather anchor evidence → check exact context → run one gap pass. Start with a soft ceiling of 12–18 searches, 4–6 fetch batches, 2–4 papers per mechanism, and 8–12 unique papers in total. Keep max_turns=30 and timeout=600 until new stop-reason and token data show where they actually bind.
05

Constrain availability, not only permission

allowed_tools auto-approves tools; it does not remove the default Claude Code toolset.

impact: medium · effort: small
Set the SDK tools option. Either inject the small bundle directly and use tools=[], or expose only Read. Keep the MCP allowlist. The latest audit shows ToolSearch and Glob being used even though the surface is supposed to be literature-only; stating exactly which tools exist removes the ambiguity and the wasted turns.
06

Add a strict pre-verification quality gate

Only program_id and mechanism name are required by the generated schema.

impact: medium–high · effort: medium
Forbid extra fields and check the invariants: 1–3 non-empty mechanisms, at least one identifier per paper, no silently dropped 4th mechanism, genes that really belong to the program, no redundant mechanisms, a PMID, DOI and title that all agree, and context claims backed by context-specific evidence. Build queries from the tool trace instead of trusting a partial agent log.

Recommended next-run profile

This deliberately steps away from the earlier “12–15 turns / 300 seconds” proposal. The four-program run we observed makes that range too aggressive. Improve tool efficiency first and collect the new stop-reason and token fields; then tighten the caps based on evidence.

Technical and biological learning

P10 is a real cilia program.Six of the top genes point to ciliogenesis, and upstream STRING already reports “cilium organization” at FDR 1.57×10⁻¹⁸. The agent found this correctly, but split one dominant piece of biology into three overlapping mechanisms.
Context and mechanism strength are different axes.Only 1 of P10’s 17 papers is “direct” brain-endothelial, yet its core ciliogenesis mechanism still holds together biologically. A general molecular mechanism can be well supported even when the evidence for its tissue context is weak.
Regulator leakage changes the question.Several modules are explained mainly through Fzd4, Eng, Notch1, Nrp1, or TGFBR1/2 while carrying only one or two program genes. That answers a question about the regulators, not about the shared function of the program itself.
Three is behaving like a target, not a maximum.All four agents returned exactly three mechanisms. In P10, ciliogenesis, ciliary Hedgehog, and endothelial cilia overlap; a flexible stop rule should let the agent settle on a single dominant mechanism when that is the honest answer.
The self-reported query log is incomplete.queries[] lists 62 entries while the audit records 116 searches. The record of where evidence came from should be built from the tool calls, not self-reported.

What “verified” does—and does not—mean

The code is honest about this in its own internal documentation, but the word “supported” can still promise a reader more than the check actually delivers.

Implemented

Identifier existence

The PMID resolves in PubMed, or the DOI resolves through Crossref or doi.org; retractions are flagged; and a network failure stays as the third state, None.

Not implemented

Scientific entailment

No step checks whether the abstract supports the mechanism summary, the named genes, or the claimed causal relationship.

Designed, not wired

Claim adjudication

The repository already sketches a claim-to-paper adjudicator, to run after verification, in docs/FUTURE_claim_verification.md.

Protocol vs schemaThe protocol requires a real PMID for every paper, but AgentPaper accepts a PMID, a DOI, both, or neither. Papers with no identifier are only dropped later.
Advertised 1–3 vs enforced shapeThe schema sets no minItems or maxItems. A fourth mechanism is dropped without warning, and zero mechanisms passes as valid.
Allowlist vs availabilityThe code treats allowed_tools as if it defined a read-only set of tools, but the SDK treats it only as a permission allowlist. tools is left unset.
Configured unique genes vs bundlebundle.py ignores top_unique=8; it emits 10 distinctive genes, all chosen from the top-loading pool.
Enrichment parameter vs bundletop_enrichment=7 is passed into bundle assembly and deliberately ignored.
Profile framing vs agent inputtissue and keyword_query are resolved and printed, but neither is put in the research bundle.
Result fields vs downstream usesupporting_regulators, contradictions, evidence_gaps, paper titles, notes, and context ratings are not passed into the annotation module context.
Earlier review vs live codedocs/pipeline_overview.html describes the retired four-question protocol, plugin literature tools, and old claims schema. It is no longer a current map.
