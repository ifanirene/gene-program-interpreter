01

What the review found

The result is not “make the prompt shorter.” That change is already present. The next quality gains come from better inputs, stricter evidence semantics, and a retrieval stop rule.

Bottom line

Keep the architecture. Change what counts as support.

One isolated session per program, in-process read-only literature tools, raw payload capture, deterministic identifier resolution, and graceful fallback are all sound. But a mechanism becomes supported when any linked PMID or DOI resolves. There is no check that the abstract entails the mechanism, that PMID and DOI refer to the same paper, or that the mechanism is driven by several program genes rather than by perturbation regulators.

KeepIsolation, PubMed fetch-before-cite, raw payloads, tri-state network verification.
Fix firstEntailment, gene-defined themes, schema constraints, dead input knobs.
Do not cut blindlyThe observed sessions needed 34–49 reported turns; a 12–15 turn cap is not evidence-based yet.

High-yield adjustments

Ordered by expected scientific gain, not by how easy the code change is. The first three change interpretation quality directly; the later items make the system cheaper and more reliable.

01

Make “supported” mean supported

Today it means only “one identifier exists and is not retracted.”

impact: very high · effort: medium
Split three axes: citation resolution, paper→claim entailment, and cell/tissue context fit. Store the canonical abstract plus a claim-specific supporting excerpt; verify that the excerpt exists; then run a small adjudicator that returns entail / neutral / contradict. Until that exists, rename the visible badge to citation resolved.
02

Define themes from program genes first

Regulators currently seed themes “the same way” as program genes.

impact: very high · effort: small
Use two passes: cluster program_genes + distinctive_genes; only then ask whether regulators reinforce, oppose, or fail to connect to those themes. Require at least two program genes for a module unless the agent explicitly marks a single-gene exception. Regulators should never satisfy the multi-gene rule.
03

Feed the agent signal already computed upstream

The bundle discards ranks, tissue, NCBI summaries, and strong enrichment hints.

impact: high · effort: small–medium
Repair the bundle: include loading rank, true unique genes outside the top-loading set, tissue, canonical gene summaries/aliases, and the top three non-redundant enrichment terms with FDR and gene overlap. Treat enrichment as a hypothesis seed, never as literature evidence. This would have revealed P10’s cilium program before dozens of single-gene searches.
04

Use an evidence budget, not a blunt turn range

Latest agents made 20–34 searches each and still logged only 53% of them in queries[].

impact: high · effort: medium
Stage retrieval: theme discovery → anchor evidence → exact-context check → one gap pass. Start with a soft ceiling of 12–18 searches, 4–6 fetch batches, 2–4 papers per mechanism, and 8–12 unique papers total. Keep max_turns=30 and timeout=600 until new stop-reason/token telemetry shows where they truly bind.
05

Constrain availability, not only permission

allowed_tools auto-approves tools; it does not remove the default Claude Code toolset.

impact: medium · effort: small
Set the SDK tools option. Either inject the small bundle directly and use tools=[], or expose only Read. Keep the MCP allowlist. The latest audit contains ToolSearch and Glob despite the claimed literature-only surface; explicit availability removes ambiguity and wasted turns.
06

Add a strict pre-verification quality gate

Only program_id and mechanism name are required by the generated schema.

impact: medium–high · effort: medium
Forbid extras and validate invariants: 1–3 non-empty mechanisms, at least one identifier per paper, no silent 4th-mechanism truncation, program-gene membership, non-redundancy, PMID↔DOI↔title concordance, and context claims backed by context-specific evidence. Derive queries from the tool trace instead of trusting a partial agent log.

Recommended next-run profile

This intentionally sits outside the earlier “12–15 turns / 300 seconds” proposal. The observed four-program run makes that range too aggressive. First improve tool efficiency and collect the new stop-reason/token fields; then reduce caps from evidence.

Technical and biological learning

P10 is a real cilia program.Six top genes converge on ciliogenesis; upstream STRING already reports “cilium organization” at FDR 1.57×10⁻¹⁸. The agent correctly found it, but split one dominant biology into three nested mechanisms.
Context and mechanism strength are different axes.P10 has only 1/17 “direct” brain-endothelial papers, yet its core ciliogenesis mechanism is biologically coherent. A universal molecular mechanism can be strong while its tissue-context evidence is weak.
Regulator leakage changes the question.Several modules are narrated mainly through Fzd4, Eng, Notch1, Nrp1, or TGFBR1/2 while carrying only one or two program genes. That is regulator mechanism research, not purely shared program function.
Three is behaving like a target, not a maximum.All four agents returned exactly three mechanisms. P10’s ciliogenesis, ciliary Hedgehog, and endothelial cilia are nested; an adaptive stop rule should allow one dominant mechanism.
The self-reported query log is incomplete.queries[] contains 62 entries while the audit records 116 searches. Provenance should be derived from tool calls.

What “verified” does—and does not—mean

The current implementation is honest in its internal documentation, but the word “supported” can still overstate the result when it reaches a reader.

Implemented

Identifier existence

PMID resolves in PubMed or DOI resolves through Crossref / doi.org; retractions are flagged; network failure remains tri-state None.

Not implemented

Scientific entailment

No step checks whether the abstract supports the mechanism summary, the named genes, or the claimed causal relationship.

Designed, not wired

Claim adjudication

The repository already sketches a post-verification claim⇄paper adjudicator in docs/FUTURE_claim_verification.md.

Protocol vs schemaThe protocol requires a real PMID for every paper; AgentPaper allows PMID, DOI, both, or neither. Identifier-less papers are only dropped later.
Advertised 1–3 vs enforced shapeThe schema has no minItems or maxItems. A fourth mechanism is silently dropped; zero mechanisms is valid.
Allowlist vs availabilityThe code calls allowed_tools a read-only tool surface, but the SDK treats it as a permission allowlist. tools is unset.
Configured unique genes vs bundletop_unique=8 is not used by bundle.py; it emits 10 distinctive genes chosen only from the top-loading pool.
Enrichment parameter vs bundletop_enrichment=7 is passed into bundle assembly and deliberately ignored.
Profile framing vs agent inputtissue and keyword_query are resolved and printed, but neither is put in the research bundle.
Result fields vs downstream usesupporting_regulators, contradictions, evidence_gaps, paper titles, notes, and context ratings are not passed into the annotation module context.
Earlier review vs live codedocs/pipeline_overview.html describes the retired four-question protocol, plugin literature tools, and old claims schema. It is no longer a current map.
